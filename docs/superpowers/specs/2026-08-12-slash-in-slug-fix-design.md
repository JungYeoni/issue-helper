# [Design] 슬러그에 남는 `/` 문자로 인한 브랜치명 충돌 수정 — 2026-08-12

## 목적

`slugify`의 특수문자 제거 정규식(`~^:?*[\]\\"'<>|`)에 `/`가 빠져 있어서, 이슈 제목에 `/`가 있으면 (예: `"README/이슈템플릿"`) 슬러그에 그대로 남는다. 이 슬러그는 브랜치명(`{타입}/{날짜}_#{번호}_{slug}`)에 그대로 들어가는데, git은 브랜치명의 `/`를 계층 구분자로 취급하기 때문에 슬러그 안의 `/`가 예상치 못한 중첩 경로를 만든다.

로컬에서 재현 확인:

```
$ git branch "feat/20260812_#8_README"
$ git branch "feat/20260812_#8_README/이슈템플릿"
fatal: cannot lock ref 'refs/heads/feat/20260812_#8_README/이슈템플릿':
'refs/heads/feat/20260812_#8_README' exists; cannot create '...'
```

같은 날짜에 이런 제목의 이슈가 여러 개 생기면, 먼저 생성된 브랜치가 이미 존재한다는 이유로 나중 브랜치를 만들 수 없는 충돌이 생긴다.

## 변경 범위

`slugify` 함수만 수정한다. `buildCommitMessage`의 커밋 메시지 본문(원본 제목)에는 적용하지 않는다 — 커밋 메시지는 git ref가 아니라 텍스트이므로 `/`가 있어도 문제없다.

## 수정 규칙

`/`를 공백과 동일하게 취급해서 구분자(`_`)로 치환한다. 단순히 삭제하면 단어가 붙어버려 가독성이 떨어지기 때문이다 (`"README/이슈템플릿"`을 `/`만 지우면 `"README이슈템플릿"`이 되어 두 단어가 구분 없이 붙는다).

```
"README/이슈템플릿" → (공백/슬래시를 구분자로 치환) → "README_이슈템플릿"
```

## 구현 방식

`scripts/suggestion.js`의 `slugify` 함수에서, 공백을 구분자로 치환하는 단계(`s.replace(/\s+/g, "_")`)의 정규식에 `/`를 포함시킨다:

```javascript
s = s.replace(/[\s/]+/g, "_");
```

이렇게 하면 공백과 `/`가 섞여 연달아 나와도(`"README / 이슈템플릿"`, `"README//이슈템플릿"` 등) 구분자 하나로 축약된다. 기존의 특수문자 제거 단계(`~^:?*[\]\\"'<>|`)는 그대로 두고 `/`는 이 정규식에 추가하지 않는다 — 이미 앞 단계에서 처리되므로 중복 불필요.

## 예시

| 제목 | 기존 slug | 수정 후 slug |
|---|---|---|
| `"README/이슈템플릿"` | `README/이슈템플릿` | `README_이슈템플릿` |
| `"A/B/C 정리"` | `A/B/C_정리` | `A_B_C_정리` |
| `"README / 이슈템플릿"` (슬래시 앞뒤 공백) | `README_/_이슈템플릿` | `README_이슈템플릿` |

## 엣지 케이스

- 제목이 `/`로만 구성된 경우(예: `"///"`) → 전부 구분자로 치환된 뒤 앞뒤 트리밍 단계에서 제거되어 빈 문자열 → 기존 로직대로 `untitled`로 대체된다.
- 이모지/대괄호 태그 제거 이후에 남는 `/`도 동일하게 처리된다 (처리 순서상 `/` 치환이 이모지·태그 제거보다 뒤에 있으므로).

## 범위 외 (Out of scope)

- `buildCommitMessage`의 원본 제목 텍스트에서 `/`를 손대는 것 — 커밋 메시지는 git ref가 아니므로 그대로 둔다.
- 이 저장소의 기존 `docs/superpowers/specs/2026-08-12-tag-and-commit-type-design.md` 예시에 있었던 `<hp:fwSpace/>` 관련 슬러그 표기 이슈 — 최종 리뷰에서 별도 후속 작업으로 분리하기로 했고, 이 스펙이 그 후속 작업이다.
