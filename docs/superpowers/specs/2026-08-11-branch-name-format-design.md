# [Design] 브랜치명 포맷 변경 (날짜 + 이슈번호 세그먼트, 언더스코어 구분자) — 2026-08-11

## 목적

브랜치명에 이슈 생성일과 이슈번호를 세그먼트로 포함시켜, 브랜치 목록만 보고도 언제/어떤 이슈에서 시작된 작업인지 바로 알 수 있게 한다. 기존에는 이슈번호와 slug만 하이픈으로 이어 붙였는데, 날짜 세그먼트가 없어 생성 시점을 알기 어려웠다.

## 변경 범위

브랜치명 포맷만 변경한다. 커밋 메시지(`feat: {원본 제목} (#{이슈번호})`)와 코멘트 템플릿의 날짜 표기(이미 `YYYYMMDD`로 별도 섹션에 존재)는 그대로 둔다.

## 출력 규칙

| 항목 | 기존 형식 | 변경 후 형식 |
|---|---|---|
| 브랜치명 | `feat/{이슈번호}-{slug}` | `feat/{YYYYMMDD}_#{이슈번호}_{slug}` |
| 예시 | `feat/123-서울-데이터-보고서-오류` | `feat/20260804_#70_구조환경지표_결측치_확인` |

- 날짜는 이슈 생성일(`issue.created_at`)을 `YYYYMMDD`로 표기한다. 코멘트의 날짜 섹션과 동일한 값·포맷을 쓴다 (같은 변환 로직을 공유).
- slug 내부 단어 구분자를 `-`에서 `_`로 바꾼다 (공백 치환, 연속 구분자 축약, 앞뒤 트림 규칙은 문자만 `_`로 교체하고 로직은 동일하게 유지).
- `MAX_SLUG_LENGTH`(50자) 제한은 slug 세그먼트에만 적용한다. 날짜·이슈번호 세그먼트는 길이 제한에 포함되지 않는다.

## 구현 방식

`scripts/suggestion.js`:

- 날짜 변환(`createdAt.slice(0, 10).replace(/-/g, "")`)을 `formatDate(createdAt)` 함수로 분리하고, `buildComment`와 `buildBranchName` 양쪽에서 재사용한다.
- `buildBranchName(issueNumber, title, createdAt)`으로 시그니처를 변경해 날짜 세그먼트를 생성한다.
- `slugify`에서 `-`를 쓰던 자리(공백 치환, 연속 구분자 축약, 앞뒤 트리밍 대상 문자)를 `_`로 교체한다. 허용/제거 문자 목록(`~ ^ : ? * [ ] \ " ' < > |` 등)은 그대로 유지한다.
- `buildComment`는 `buildBranchName`에 `createdAt`을 그대로 전달하도록 호출부를 수정한다.

## 엣지 케이스

- slug가 특수문자만 있어 빈 문자열이 되는 경우 → 기존과 동일하게 `untitled`로 대체 (예: `feat/20260804_#70_untitled`).
- 제목이 50자를 넘는 경우 → slug 세그먼트만 50자로 잘리고, 날짜·이슈번호 세그먼트는 영향받지 않는다.

## 참고 사항 (제약 아님)

브랜치명에 `#`이 포함되지만 `git check-ref-format` 기준으로 허용되는 문자라 브랜치 생성/체크아웃에는 문제가 없다. 셸에서 인자 중간에 오는 `#`은 주석으로 해석되지 않으므로 명령줄 사용 시에도 별도 이스케이프가 불필요하다. 다만 GitHub 웹 UI나 외부 도구가 브랜치명을 URL에 그대로 넣을 경우 `#`이 fragment 구분자로 해석될 수 있다는 점은 참고만 해둔다.

## 테스트 방법

- `scripts/suggestion.test.js`의 기존 하이픈 기반 기대값(`buildBranchName`, `slugify` 관련 테스트)을 새 포맷(언더스코어 + 날짜 + `#이슈번호`)에 맞게 갱신한다.
- `buildBranchName` 테스트에 `createdAt` 인자를 추가하고, 날짜 세그먼트가 올바르게 생성되는지 검증하는 케이스를 추가한다.
- 한글 제목, 특수문자 포함 제목, 매우 긴 제목(50자 초과) 각각에 대해 새 브랜치명 포맷이 기대한 대로 나오는지 확인한다.
